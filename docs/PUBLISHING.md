# Publishing and identity

The initial publication target is [highreading/e-plus-pi-open-research](https://github.com/highreading/e-plus-pi-open-research). This release imports no private Git history, account token or personal commit-author configuration. Its initial snapshot uses an anonymous author and committer with a generic GitHub noreply address. The release is uploaded privately, retrieved and verified against the reviewed byte inventory, and then made public.

For later releases, read [publication coverage](PUBLICATION_COVERAGE.md) and run the standalone release validator. Upload only the sanitized repository contents. Private preservation archives and preparation receipts remain outside the public package. Keep local environment files, raw chats, API keys, screenshots and operating-system sidecars out of submissions.

Repository and hosting metadata are separate from file contents. The repository owner account is visible on GitHub. Contributor accounts, commit identity, issue activity and linked profiles may identify participants even when their files are anonymous. Choose public identities deliberately; do not inherit a local personal name or email into a research commit.

This release uses the CC0/MIT policy in [reuse and attribution](../REUSE.md), with third-party rights retained. The real repository address is included in [citation guidance](../CITATION.md); private origin paths are omitted.

Use [the community invitation](../COMMUNITY_INVITATION.md) to introduce the project. Issues and Discussions support bounded tasks, review requests and duplicate-work checks. Keep the proof-status ledger visible and distinguish submitted results from reviewed ones. A privacy or link checker must never be advertised as a mathematical proof checker.
